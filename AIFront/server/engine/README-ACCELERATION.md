# 引擎加速能力说明

目标：在保证效果的前提下，让「提需求 → 模型响应」更快，减少无效等待。

## 1. 算法与策略（已实现）

### 1.1 并行代码生成（最优循环算法）

- **位置**：`server/index.js` 中 execute 的 codegen 阶段。
- **原逻辑**：对 N 个 action 串行执行 `for (i=0; i<N; i++) await codegen(action[i])`，总耗时 = T1+T2+…+TN。
- **现逻辑**：`Promise.all(actions.map(runOne))`，多个**相互独立**的 add_view / modify_view 同时请求模型。
- **效果**：总耗时 ≈ **max(T1, T2, …, TN)**，多文件改动时接近「只等最慢的那一次」。
- **适用**：规划结果里有多条独立改动（如同时改 A.vue 和 B.vue）时自动生效。

### 1.2 规则短路（零次 / 最少 LLM 调用）

- **路由 (router)**：`ruleBasedRoute` 对「优化 + 样式/颜色/布局/美观/卡片/高度/间距/视觉/统一」等直接返回 `modify_existing` + 目标文件，**不调 LLM**。
- **规划 (planner)**：`ruleBasedPlan` 对上述同类意图直接返回单条 `modify_view` action，**不再调 LLM**。
- **效果**：例如「优化指令市场样式」全链路可做到：分析(缓存) + 路由(规则) + 规划(规则) + **仅 1 次 codegen**，整体比「路由+规划各 1 次 + codegen 1 次」少 2 次模型调用。

### 1.3 分析缓存

- **位置**：`server/engine/analyzer.js`。
- **逻辑**：项目结构分析结果 15s 内复用，重复请求不重复扫盘。
- **效果**：连续操作时首包更快、负载更低。

### 1.4 样式快速路径（codegen 内部）

- **位置**：`server/engine/codegen.js` 中 `generateForModifyView`。
- **逻辑**：若指令明显是「样式/美观/布局/颜色/字体/间距」，优先走 `tryStyleOnlyModify`，只重写 `<style>` 块，不重写整页；且该次调用使用较小 `max_tokens`（如 2048），缩短单次模型响应时间。
- **效果**：样式类需求单次模型耗时更短，且避免整页重写带来的风险。

### 1.5 样式保留能力（style-preserve）

- **位置**：`server/engine/style-preserve.js`，在 `applier` 写入 .vue 前调用。
- **逻辑**：按「视图文件名」配置「必须保留的样式片段」（如 CommandMarket.vue 的图标配色、.meta-*、卡片高度等）。每次引擎写入该 .vue 时，检查新 style 是否已包含这些选择器；若缺失则自动追加对应 CSS，再写盘。
- **效果**：即使用户或 LLM 把某页「优化」成黑白或删掉关键选择器，项目在写入前会自动补全，保证配色与布局不丢。
- **扩展**：新增页面或新关键样式时，在 `PRESERVE_REGISTRY` 里为对应视图增加 `{ id, selector, css }` 即可。

### 1.6 短期结果缓存（execute 缓存）

- **位置**：`server/index.js`，在 `/api/engine/execute` 入口。
- **逻辑**：按「消息内容 + 当前文件」生成缓存 key，45 秒内相同请求直接回放上次的 eventLog（不调路由/规划/codegen），前端秒出结果。
- **效果**：重复点击、重试、误触同一句「优化指令市场」时不再重复调模型，明显减轻「超级慢」体感。

### 1.7 默认缩 token 与快速模式

- **默认**：整页修改 max_tokens 已改为 3072（原 4096），单次生成更短、响应更快。
- **环境变量**：`DEEPSEEK_FAST_MODE=1` 时，样式快速路径进一步用 1536，整体更快（略增截断概率）。

## 2. 可调参数（环境变量）

- `DEEPSEEK_MAX_TOKENS`：整页修改时的最大生成长度，默认 3072（原 4096）；设大则更不易截断但更慢。
- `DEEPSEEK_FAST_MODE`：设为 `1` 或 `true` 时进一步压低 token（修改 3072、样式 1536），优先速度。
- `DEEPSEEK_STYLE_MAX_TOKENS`：样式专用路径上限，默认 2048，快速模式下 1536。
- `DEEPSEEK_TIMEOUT_MS`：单次请求超时（毫秒），默认 120000。

## 3. 与 Cursor 的差异（本引擎的加速点）

- **并行 codegen**：多文件改动时并行请求，而不是严格串行。
- **规则优先**：高频、明确的「优化样式/视觉」类需求直接走规则，路由+规划零模型调用。
- **样式专用路径**：只改样式时只生成 style 块，减少 token 与时间。
- **分析缓存**：同一会话内重复分析用缓存，减少 I/O 与重复计算。

以上能力共同作用，使「写个页面、改个样式」类需求在多数情况下能更快返回，且保持业务逻辑与页面可用性。
